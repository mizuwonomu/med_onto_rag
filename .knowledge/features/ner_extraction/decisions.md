# decisions.md — NER extraction layer

## Chosen approach + why

**The LLM generates only `text`/`type`/`assertions`** (branch `llm-assertion`, base `7691c74`, 2026-08-02). Positions come from `align.py` and codes from `linker.py`. Positions were withheld because character counting is exactly what a language model is worst at while `str.find` does it perfectly and free; the organizer's own documentation proved the point, listing `[58, 83]` for a span that is actually at `[56, 81]`. Codes were withheld because a model reciting ICD/RxNorm from memory is unanchored to the KB that is actually being scored.

**Verbatim is repaired downstream, not enforced upstream** (2026-08-02). The prompt asks for character-exact spans, but nothing can *force* it: GBNF constrains shape and never sees `input_text`, so it cannot check whether a string occurs in the source. Instead `align_positions` overwrites `text` with the raw slice once the span is located. The model therefore only needs to be *close enough to find*, not exact — a materially easier requirement, and the right split for a 9B model where capitalization and Unicode drift are near-certain.

**Alignment uses a forward cursor, and fuzzy matching is restricted to deterministic transformations** (2026-08-02). Repeated mentions are ordinary in clinical notes (`táo bón` twice, `chụp ct sọ não` twice in `data/input/22.txt`), and a plain `str.find` collapses both onto one offset, which the organizer scores as a single duplicated concept. The fuzzy fallback normalizes only NFC composition and case; edit-distance was rejected because it would happily bind `đau bụng` to `đau lưng` somewhere in the document, fabricating a mention with a structurally valid position — worse than dropping it.

**Routing by entity type, with code-shape checking demoted to an assertion** (2026-08-02). Only `CHẨN_ĐOÁN` reaches ICD and only `THUỐC` reaches RxNorm; the other three types never touch retrieval. Not for GPU economy but because the KBs contain no matching concept: asking ICD about `sốt cao` still returns some code with some score, and a floor calibrated on genuine diagnosis mentions has no reason to reject it. `check_code_shape` runs *after* `expand_codes` purely to catch crossed store wiring — a configuration error that would pass every test while corrupting all results.

**One system message, not two** (2026-08-02). Qwen3.5's chat template raises `System message must be at the beginning`, and llama-server returns HTTP 400 rather than a warning. Rules and few-shot are concatenated into a single message. No prompt-cache cost: llama.cpp caches KV by common prefix, not by message boundary.

**Entity count capped in the grammar via `maxItems`, not in the prompt** (2026-08-02). See the failed-approaches entry on decoding loops; `MAX_ENTITIES_PER_DOC` lives in `configs/config.py` and reaches the grammar through Pydantic's `max_length`.

**Jaccard is asymmetric, and the asymmetry decides threshold policy** (2026-08-02). For gold size `n`, returning `m` codes too many scores `n/(n+m)` while returning `m` too few scores `(n-m)/n`; the gap is exactly `m^2/(n(n+m))`, so over-returning always beats under-returning. It matters most at `n = 1` (0.5 vs 0.0) and fades fast (0.083 at `n = 3`). The genuinely fatal case is the empty prediction: gold non-empty + prediction empty is a hard 0, so a floor must never be allowed to empty a candidate list. Conversely gold empty + prediction non-empty is also 0, which is why `TYPES_WITH_CANDIDATES` is load-bearing rather than cosmetic - staying silent on a code-less type is worth a free 1.0.

**Every concept is a candidate `k`, including the ones that carry no codes** (2026-08-02, inferred not confirmed). The `+1` in the organizer's weight `len(ground_truth(k)) + 1` only has a reason to exist under this reading: if `k` ranged over coded concepts only, `len(gt) >= 1` always and the `+1` would be inert. Under this reading a correctly extracted TRIỆU_CHỨNG or lab field earns 1.0 on both `assertions` and `candidates` for free, which makes the lab branch the cheapest points in the task. The harness therefore reports both an inclusive and a KB-only figure as the two ends of a band, because the organizer never states which applies.

**RxNorm stays ingredient-level (`tty = 'IN'`)** (branch `evals`, `8bba52d`, 2026-08-03). Adding `SCD` was implemented, indexed, and submitted twice; it cost `-1.05` on `J_candidates` against an identical NER layer. The arithmetic is decided by the input, not by the gold format: at most 24 dose-bearing mentions could gain, while ~157 bare-name mentions had their correct ingredient displaced from rank 1 by strength-level siblings. A losing trade by construction, not an under-tuned one.

**`RETRIEVAL_THRESHOLDS["rxnorm"]` keeps `margin = 0.0`** (same anchor). Widening to `0.2` was the Jaccard optimum on the 11-mention fixture (`J = 0.394` vs `0.273`) and scored `+0.209` on the SCD KB - but `-0.065` on the ingredient KB. Not a consistent gain, and an order of magnitude below the KB effect either way.

**`query_variant` is now `raw` for RxNorm** (same anchor). Not because it wins: `raw` and `strip_dose` produced **byte-identical scores** (`9.1937` twice) on the real submission. At ingredient granularity dose tokens match nothing in the KB text, so stripping them removes noise rather than signal - the earlier claim that `strip_dose` *wins* was an artifact of the synthetic set, whose gold was ingredient-level by construction. `raw` is kept as the simpler of two equivalent options.

**Formal span rules are enforced in `align.py`, not in the prompt** (branch `evals`, `c8d3e7f`, 2026-08-04). `postprocess()` drops asterisk-only spans, drops a span fully contained in another of the same type, and trims a trailing severity adverb. The division of labour matches the one already drawn for positions and codes: what a string comparison decides perfectly is never delegated to a 9B model. Measured on the organizer's scoreboard, this moved all three metrics at once - `WER 77.8966 -> 77.6252`, `J_assertion 26.7302 -> 26.9255`, `J_candidates 9.1937 -> 9.2314`, total `18.3275 -> 18.4827`.

**A trim is admitted by a condition on what remains, not by a deny list** (same anchor). The rule is: at least two words must survive the cut. On the real submission every wrong cut left exactly one word (`tiểu ít` -> `tiểu`, `sốt nhẹ` -> `sốt`, `uống nhiều` -> `uống`) while every correct cut left two or more (`kích thích nhẹ` -> `kích thích`, `buồn nôn thoáng qua` -> `buồn nôn`). The linguistic reason: in a two-word phrase the second word usually *names* the finding - `tiểu ít` is oliguria, `uống nhiều` is polydipsia - whereas in a longer phrase the trailing adverb only *grades* a concept that is already complete. A deny list was tried first and was incomplete after every round; a condition on the remainder covers cases never seen. One deny list survives (`_SEVERITY_BOUND`) for `Bệnh amyloidosis chuỗi nhẹ`, where `chuỗi nhẹ` is the translation of *light chain* and three words still remain after the cut.

## Assumptions it rests on

- **Gold spans are shorter than what the model emits.** Every trim rule assumes the organizer records `kích thích`, not `kích thích nhẹ`. Never verified against gold - inferred from the organizer's own examples (`ho đờm xanh`, `tức ngực`) being uniformly short.
- **A one-word remainder is never the intended concept.** True for every case observed, but it is a heuristic about Vietnamese medical phrasing, not a rule of the task. It deliberately gives up trims that would have been correct (`sốt cao` -> `sốt`), on the grounds that a wrong cut fabricates a different concept while a missing cut only costs part of one WER.

- **The 100-document test set is representative of the final evaluation set.** The `24/157` dose ratio comes from our own predictions on it. If the real distribution were dose-heavy, the SCD decision reverses.
- **Gold for a bare drug name is ingredient-level.** Inferred from score movement across submissions, never observed directly - the organizer publishes gold for 13 RXCUIs, all from dose-bearing mentions.
- **The NER layer is unchanged across all five submissions.** `WER 77.8966` and `J_assertion 26.7302` are identical to four decimal places in every run, which is what makes the `J_candidates` deltas attributable to retrieval alone.

- **Documents fit in one context window.** Prompt is ~4.2k tokens; the organizer's longest input (`data/input/3.txt`) is ~1.5k. With `max_tokens` at 2048 the total lands near 7.8k, so `-c` must exceed that with margin. Any prompt growth eats this budget directly — the layer has no chunking strategy, and adding one would break the position contract since offsets must index the whole document.
- **Mentions are contiguous substrings.** Discontinuous concepts ("đau *và sưng* khớp gối" meaning two findings sharing a head) cannot be represented at all: `position` is a single `[start, end]` pair.
- **The reranker thresholds transfer from calibration mentions to NER output.** `RETRIEVAL_THRESHOLDS` was tuned on 399 clean synthetic mentions; real extracted spans carry boundary drift and modifiers. This is the first layer to actually exercise those numbers, and nothing yet confirms they hold.
- **`configs/config.py` imports nothing from the repo.** Every module depends on it, so it must stay a leaf. Violated once during this work (`config` ↔ `extract.schema`) and every import in the project failed immediately.
- **Greedy decoding stays viable.** `temperature = 0` is kept for reproducibility, which is what made the degeneration loop possible in the first place; the mitigations are a repeat penalty and a grammar cap rather than sampling.

## Failed approaches

- Tried: **Per-character NFC normalization to build the fuzzy offset map** — Failed because: NFC is a *composing* transform (`u` + combining circumflex + combining acute → `ấ`); normalizing one character at a time never lets the marks meet their base, so an NFD document stays NFD and every fuzzy comparison against an NFC needle misses — the exact case the fallback exists to rescue. Fixed by folding the whole string and building the index map from prefix lengths (`len(_fold(raw[:i]))`). — Avoid when: writing any offset-preserving Unicode mapping; the temptation is that per-character feels like the only way to keep offsets traceable.
- Tried: **`max_tokens` as the defence against runaway generation** — Failed because: it bounds the damage without preventing the cause. Measured on the probe sentence `Bệnh nhân sốt cao, không ho.`, the model emitted three correct concepts then looped `sốt cao → ho → không ho` until the budget was gone. Raising the limit only buys the loop more room. GBNF constrains *shape*, not *length*, so an arbitrarily long array stays valid; `maxItems` is the only thing that makes the grammar close the array. — Avoid when: a length-limit error looks like "the model needs more room" — check whether the output is repeating first.
- Tried: **Reusing the organizer's worked examples verbatim as few-shot** — Failed because: they are final-submission records carrying `candidates` and `position`, which teaches the model to generate fields the grammar forbids, creating a pointless tug-of-war. They also contain a mention (`TWBC`) absent from their own input, which would teach the model to invent spans that `align.py` then discards. — Avoid when: an official example exists and looks authoritative; check it against the schema the model actually generates under.
- Tried: **Scoring by exact `(text, type)` matching only** (evaluation harness, not shipped code) — Failed because: boundary-drifted mentions failed to pair and were therefore excluded from the sample, leaving only perfect matches to be scored — so `text_score` read `1.0000` regardless of model quality. Adding an overlap-matching second pass moved it to `0.6917` on the same predictions, with the model unchanged. — Avoid when: a metric looks suspiciously perfect; check what the pairing step silently dropped.
- Tried: **Leaving `--reasoning` at llama-server's default** — Failed because: the default is `auto`, which detects Qwen3.5 as a reasoning model and enables thinking. Every token went to `reasoning_content` with `content` empty, so the request died on a length error before producing any JSON — a symptom that reads as "the model is too weak" when it never got a turn to answer. — Avoid when: deploying any recent instruct model for structured output.

- Tried: **Trusting recall measured on the 399-row synthetic set** - Failed because: the synthetic gold codes were drawn *from the KB being searched*, so every answer was reachable by construction. The measurement could only ever confirm that the index contains what the index contains. Against the organizer's gold, `viêm bao tử` returns zero digestive codes in the BM25 top-30 and the two drug RXCUIs are not in the KB at all. - Avoid when: gold and index share an origin; recall measured that way is circular and says nothing about coverage.
- Tried: **Reading `J_candidates` as a reranker problem** - Failed because: BM25 on the formal term `viêm dạ dày` puts K29* at ranks 1-6, while the colloquial `viêm bao tử` puts it nowhere in the top 30. The reranker never sees the right candidate, so a larger reranker (the direction recorded under the retrieval feature) would change nothing. - Avoid when: a linking score is low; check retrieval@k for the gold code *before* touching the ranking stage.
- Tried: **A 50% containment gate in the evaluation harness** - Failed because: a threshold of exactly 50% cannot reject a pair that overlaps by exactly 50%. `đau bụng` / `đau ngực` share `đau ` = 4 of 8 characters and `4 >= max(3, 8//2)` is true, so the gate admitted the very case its docstring claimed to block. Raised to 60%, the smallest margin that still keeps `sốt` vs `sốt cao`. - Avoid when: writing any ratio gate; the boundary case is the one the rule exists for.
- Tried: **Dice as the admissibility gate for pairing** - Failed because: Dice punishes length mismatch hard, and boundary drift is the most common error of this layer. `đau bụng thượng vị dữ dội liên lục` vs gold `đau bụng` scores 0.381, *below* the junk pair `đau bụng`/`đau ngực` at 0.500 - so a Dice gate rejects the pairs that must be scored and keeps the ones that must not. Containment answers "same concept?", Dice answers "which gold fits best"; they are different questions and need different measures. - Avoid when: one number is being asked to both admit and rank.

- Tried: **Widening the RxNorm export to `SCD` so the organizer's gold codes exist in the KB** (2026-08-03) - Failed because: the premise was true (`308135`, `1660761` were genuinely absent) but the inference from it was wrong. Coverage of the *published examples* is not coverage of the *test set*: 87% of real drug mentions are bare names whose gold is ingredient-level, and 17,552 new strength-level concepts displaced them from rank 1. Scored `8.1404` against a `9.1937` baseline with an identical NER layer. - Avoid when: a missing gold code proves a KB gap; measure how many inputs actually resemble that gold before widening. **Cross-cutting - pointer promoted to `index.md`.**
- Tried: **Choosing `margin` from the 11-mention gold fixture** (2026-08-03) - Failed because: the fixture is drawn from the organizer's worked examples, which are dose-bearing prescription lines, so gold sat at rank 2 in 6 of 11 cases and widening `margin` looked strongly positive (`J` 0.273 -> 0.394). On real input, where most gold is already at rank 1, the same change only dilutes `J = 1.0` into `J = 0.5`; it measured `-0.065`. The fixture pointed the wrong way twice in one session - first on SCD, then on `margin`. - Avoid when: a fixture is small and curated. It can validate reachability but never a threshold, because a threshold is a property of a distribution and a fixture has none.
- Tried: **Raising `TOP_K_DENSE`/`TOP_K_BM25` to rule out under-retrieval** (2026-08-03) - Failed because: never run, and it should not be. `--show-rank` had already shown gold inside the candidate list in every `raw` case (ranks 1, 1, 1, 2, 2, 2, 2, 2, 2, 11, 31), with exactly one absence and that under `strip_dose`. The defect was rank *within* what was retrieved, not what was retrieved. - Avoid when: a linking score is low and top-k is the obvious knob; check whether gold is present-but-outranked first, because top-k cannot fix precision at the head.
- Tried: **Sweeping thresholds on the 399-row synthetic set after the KB change** (2026-08-03) - Failed because: its RxNorm gold is ingredient-level (`amoxicillin 400 mg po qid` -> `723`, the bare ingredient), so it teaches "strip the dose, return the ingredient" - the opposite of the SCD rule being tested. Sweeping there would have optimized confidently for the wrong problem. - Avoid when: the KB changes granularity; the calibration set encodes the old granularity inside its gold and stops being valid silently, with no error and no warning.

- Tried: **Tightening span length by adding rules and examples to the prompt** (2026-08-04) - Failed because: the MINIMAL SPAN block already held seven bullets, and an eighth changed almost nothing - the severity-tail violation count moved `81 -> 80` across 100 documents, including for the exact words written out in the rule and the exact phrases used as examples (`nhịp tim chậm nặng`, `kích thích nhẹ`). Instruction capacity for formal constraints is saturated well before the context window is. - Avoid when: a compliance count is high and the obvious fix is a clearer rule; check first whether the rule is decidable by string comparison, in which case code enforces it and the prompt cannot.
- Tried: **Loosening `KẾT_QUẢ_XÉT_NGHIỆM` to admit qualitative verdicts** (2026-08-04) - Failed because: the model learned "a result need not contain digits" without learning where the span ends, so the same flag it was meant to reduce **doubled**, `48 -> 91`. New failure shapes appeared that had not existed before: `chụp ct sọ não: âm tính` (the test name swallowed into the result) and `dương tính xét nghiệm phân tìm cryptosporidium`. Total records rose `1966 -> 2172` while the goal was to remove surplus. - Avoid when: relaxing a constraint to admit a handful of correct cases; count how many wrong cases the same relaxation admits, and prefer a whitelist to a loosened definition.
- Tried: **Adding a fifth few-shot example to break the test-name/test-result pairing** (2026-08-04) - Failed because: the four existing examples all show tests paired 1:1 with their results, and the counts `187 = 187` on real data showed the model reproducing that shape rather than reading the text. A fifth example showing tests without results produced `254` vs `252` - still 1:1, just larger. The model added concepts instead of withholding them. - Avoid when: an output shape looks like imitation of the few-shot; adding a counter-example teaches an additional pattern rather than replacing the dominant one.
- Tried: **A deny list of phrases exempt from severity trimming** (2026-08-04) - Failed because: it can only contain cases already seen. Four entries covered `nhịp tim chậm` and its neighbours, then real data produced `tiểu ít`, `đau vừa`, `sốt nhẹ`, `uống nhiều`, `Ăn nhiều`, `Bệnh amyloidosis chuỗi nhẹ`, each requiring another entry. Replaced by a condition on the remainder, which covers unseen cases by construction. - Avoid when: writing any exemption list; ask whether the property that makes those cases exempt can be stated about the result instead.

## Nuances agreed with the user

- **`suppress = 'O'` and `'E'` were considered and deliberately excluded** from candidates (2026-08-03). Obsolete SCDs are mostly discontinued strength variants of active drugs, so they crowd exactly the sibling cluster the reranker already loses on, while gold never selects them. This also preserves the layer's existing asymmetry: alias docs keep `suppress='O'` so discontinued brand names stay findable, but what they resolve *to* must be currently active.
- **`PSN` was evaluated as a synonym source and rejected.** It duplicates the SCD string with tall-man letters (`amLODIPine besylate 10 MG Oral Tablet`) rather than adding vocabulary, and BM25 is already case-insensitive. Case folding belongs in the tokenizer, not in a duplicated document string.
- **RXNREL / `rela` was deliberately not touched.** The 11 gold mentions contain no brand names, and the organizer redacts drug names with asterisks - which is exactly where brand names would appear. Brand-to-generic traversal has little to act on, and it is the one part of this layer with a history of silent namespace bugs (RXAUI vs RXCUI); adding it alongside a granularity change would have made two risky edits inseparable.
- **`360047` was left unresolved.** It is absent from `rxnconso` entirely while 12 of 13 gold RXCUIs are present, so it is an outlier rather than evidence of a truncated release. `rxnatomarchive` has never been loaded, and loading a table to chase one code in thirteen was not worth it while 181 records were believed to score zero for a different reason.

- **Gold labels were corrected against the prompt's rules, not the other way round**, in five cases where the two disagreed. Negation words belong to the assertion, not the span (`không ợ hơi` → `ợ hơi` + `isNegated`), matching the organizer's own `"không ho"` example. History framing likewise (`tiền sử cá nhân có khối u lành tính` → `khối u lành tính`). One case was deliberately left alone: `không thể ngủ` means insomnia, a positive finding, so splitting it would distort the meaning rather than clarify it.
- **`CHẨN_ĐOÁN` vs `TRIỆU_CHỨNG` is decided by the phrase, never by the section.** Gold data contains both labels under identical `Tiền sử ... ghi nhận bị` framing: `tăng huyết áp vô căn` is a diagnosis (clinical qualifier) while `gãy vai` and `quáng gà` are symptoms (bare descriptions). An earlier hypothesis — that `isHistorical` implies `TRIỆU_CHỨNG` — was tested against the gold distribution (1 diagnosis vs 10 symptoms with that assertion) and rejected: the correlation is real but the causal direction is wrong, and encoding it would have broken the one diagnosis case.
- **Normal physiological states are symptoms, not diagnoses.** `thai nghén` alone is `TRIỆU_CHỨNG`; only with a complication (`suy giảm miễn dịch HIV gây cho thai nghén`) does it become `CHẨN_ĐOÁN`. Stated as a general principle rather than a keyword list, since a keyword list fails on any term the test set happens not to share.
- **Prompt tuning was stopped deliberately** after three rounds, once the remaining errors stopped repeating across documents. Each round had used the failing cases as new examples; continuing would have been memorizing ten documents rather than teaching a rule — the same overfitting trap already recorded for the ICD thresholds.
- **The synthetic set is hand-authored gold with LLM-written prose.** The user writes the entity list and the model only renders it into a clinical narrative, because letting a model produce gold reproduces exactly the errors being measured — observed directly when generated gold silently corrected `đau châ` and absorbed framing into spans.

# log.md (feature narrative, durable)

This session built the retrieval layer proper — the stage between the vector index and the future NER pipeline — plus the measurement machinery needed to calibrate its thresholds. It ran from a pre-agreed plan (`retrieval_layer.md`), but diverged from it in several places, and the divergences are the interesting part.

Work proceeded **gate-first**. `scripts/retrieval/validate_synthetic.py` was written before any measurement, on the reasoning that a wrong gold label poisons every downstream number invisibly. That ordering paid for itself immediately: the gate rejected the calibration set named in the plan before a single GPU second was spent. The plan pointed at `rxnorm_icd_synthetic_400-v2.jsonl`, which turned out to carry only `{mention, kb, gold, noise}` — none of the `distractor`, `cluster_name`, `gold_kind` fields the plan depends on. The correct file was a `-labeled` variant, and the plan's `multi_resolve` label was actually `multi_solving` in both the data and the pre-existing `scripts/validate_test_set.py`.

The gate then drove five rounds of dataset regeneration. It caught, in order: 94 exactly-duplicated rows concentrated in `noise=heavy`; a cluster spanning two ICD blocks; mentions contaminated with fragments of the string `"rxnorm"` leaked in by the noise injector; `cluster_name` perfectly correlated with `noise` (every mild row clustered, every heavy row not — two names for one variable, which would have made "is heavy noise hard, or is hard-negative structure hard?" permanently unanswerable); distractors drawn from a broad concept group rather than the cluster's own siblings; single-member clusters; twelve clusters so large that 300 rows collapsed into 12 split units; `multi_solving` rows whose golds shared no `resolve_in`; and `multi_sibling` rows spanning ICD blocks. The gate's own rules were corrected once along the way — the "distractor must be another row's gold" rule proved too strict and was replaced with region membership (see `decisions.md`). The final set reached **0 errors on 399 rows**, with 50 clusters of exactly 6 rows and all four `noise × cluster` cells populated.

The library was built bottom-up with one deliberate asymmetry: `BM25SRetriever` is a `BaseRetriever` because it owns real state (index, corpus, persistence with a sidecar `documents.jsonl` so reload never re-reads the KB), while the dense side is a plain `dense_search` function because Chroma already owns that state and wrapping it in `VectorStoreRetriever` would silently discard the scores. Both branches are built from the *same* loaders as the vector index, which is what makes hybrid union a plain set-union over `doc_id`.

Measurement was structured so **GPU is touched exactly once**. `dump_scores.py` writes raw scores plus every source field to JSONL, after which sweeping, bootstrapping and re-plotting cost nothing. This is what made it affordable to re-run the entire calibration end-to-end after the dataset was regenerated — one 35-minute dump, then free analysis.

Analysis is deliberately staged before optimization. `analyze_distribution.py` answers "is there room for a threshold at all" — the gap between gold and non-gold (floor's headroom), the minimum margin needed to cover all gold (floor of margin), and the gold-to-distractor gap (ceiling of margin) — because a sweep always returns an optimum, including when the distributions overlap and that optimum is meaningless. One measurement bug was found and fixed here: the margin floor was initially computed as the score spread between gold *documents*, which reported RxNorm as needing margin ≈ 5.16 when it needs 0, because one alias document already expands to the whole gold code set. Measuring over expanded **codes** fixed it and reversed a false "no margin can satisfy every row" verdict.

`sweep_thresholds.py` then picks (floor, margin) per KB with three anti-self-deception devices: a cluster-aware sweep/dev split, ~300 bootstrap resamples re-picking the optimum each time, and a distractor-leak report broken down by cluster name so failures are actionable rather than aggregate. The grid is derived from the observed score distribution rather than hardcoded, since reranker logits have no fixed scale.

Two findings shaped the outcome. First, the plan assumed one query variant would be chosen globally; measurement showed each KB wins under a different one, so the variant became a per-KB setting alongside the thresholds. Second, an apparent anomaly — the reranker seeming to score distractors very highly in the histograms — was investigated and rejected: `density=True` normalizes each label group independently, so the bar heights were not comparable. Head counts showed the right tail is nearly pure gold; the real overlap sits mid-scale.

**Result.** On the final 399-row set: recall@union 0.935 overall (ICD 0.905, RxNorm 0.965, heavy-noise 0.850, `multi_solving` 1.000). RxNorm is calibrated and **frozen** at floor 2.157 / margin 0.0 under `strip_dose`, with bootstrap returning an identical floor on all 300 resamples, sweep−dev = +0.0004, and 0% distractor leak across all clusters. ICD is **tentative** at floor 1.490 / margin 0.399 under `raw`; its bootstrap is now stable (`[1.490, 1.890]`, down from `[0.014, 3.807]` before the cluster count was raised) but sweep−dev = +0.104 remains. 133 unit tests pass, covering the tokenizer, threshold logic, code expansion, the scoring formula against hand-computed vectors, the split invariants, and every gate rule. The definition of done is met except for the ICD half of "thresholds produced with stable bootstrap and no anomalous sweep-vs-dev gap" — and the diagnosis for that gap is recorded in `tracker.md` as a reranker limitation, not a data-volume one.

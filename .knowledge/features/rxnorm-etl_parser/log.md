# log.md (feature narrative, durable)

Work began by porting the MySQL RxNorm loader (`Table_scripts_mysql_rxn.sql`, `Load_scripts_mysql_rxn_win.sql`) to PostgreSQL. DDL translated with no changes beyond formatting. The loader did not: `LOAD DATA LOCAL INFILE` became server-side `COPY`, which forced three successive corrections, the trailing-pipe filler column, the invalid `QUOTE` option in `text` mode, and finally the backslash-escape collision that required moving to `FORMAT csv` with a rare-character `QUOTE`/`ESCAPE` pair. Environment friction consumed real time: PostgreSQL runs inside WSL while the RRF files began on a Windows drive, so paths had to be resolved through `/mnt/d/` and then relocated to the ext4 side for throughput; server-side `COPY` additionally runs as the `postgres` system user, which cannot traverse a default-permissioned `/home/<user>` and cannot write into a user-owned `/tmp` subdirectory.

With the tables loaded, the export layer was designed against a concrete downstream requirement: prescription text frequently names a brand where the linking target is a generic ingredient, so retrieval must match on brand strings yet return generic codes. The design separates _findability_ from _identity_. Alias docs carry brand text for matching and nothing but resolution pointers as payload; candidate docs carry generic identity and same-concept synonyms. Because every brand-to-generic hop is materialized into `resolve_in` / `resolve_min` at export time, the runtime path is retrieve then read metadata, with no graph traversal and no database access.

The RXAUI-to-RXCUI correction was the pivotal moment. The initial export drew resolution codes from the gatekeeping RXNCONSO join, producing atom identifiers throughout. The user caught this against known gold examples (`360047`, `1660761`, `308135`, `7597`, all RXCUIs) and identified the underlying cause: RXNCONSO had been used as a data source when its only role was validation. Both export queries were rewritten so the code comes from `rel.generic_rxcui` and RXNCONSO appears solely inside `EXISTS`.

Outcome: three SQL files produce JSONL directly loadable as LangChain `Document`s. Definition-of-done for the export shape is met. Definition-of-done for _correctness of coverage_ is not yet met, as the `rela` filter question below remains open.

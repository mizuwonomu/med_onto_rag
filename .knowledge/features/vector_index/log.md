# log.md (feature narrative, durable)

This is the first step of the retrieval layer: turn the three processed KB JSONL files into LangChain `Document`s and embed them into two on-disk Chroma indexes. It was executed from a pre-agreed plan (`vector_index.md`), so most of the design was settled before coding; the narrative here is about how it actually landed and where it diverged.

The load side (`index/load_documents.py`) reads each JSONL line, NFC-normalizes the `text` field into `page_content`, and routes everything else into scalar-only metadata. ICD records carry the full flat schema; RxNorm splits into candidate docs (`c_<rxcui>`, with a `synonyms` list) and alias docs (`b_<rxaui>`, with parallel `resolve_in`/`resolve_min` lists). Lists become JSON strings, empty/None keys are dropped, records missing `doc_id`/`text` are skipped with a count, and duplicate `doc_id`s within a KB are collapsed to the first occurrence with a warning.

The ingestion side diverged from the plan on the user's call: instead of a single `ingestion.py` owning both the Chroma writing and the model orchestration, it was split. `ingest_collection()` in `index/ingestion.py` is now a pure, embedding-agnostic writer — it takes any `Embeddings`, wipes and rebuilds a Chroma collection in batches keyed by `doc_id`, and verifies the final count. The Qwen-specific parts — device/fp16 selection, the asymmetric query-vs-document prompt, the norm/asymmetry sanity check, and the two-collection orchestration — live in `index/build_vector.py`, the `python -m index.build_vector` entrypoint. The reason was reuse: the coming BM25/hybrid work and any embedding swap can drive `ingest_collection` without touching Qwen wiring.

The one genuine surprise came from tests. The idempotency test (ingest the same docs twice in one process) failed with `attempt to write a readonly database`. The cause was chromadb's process-level `PersistentClient` cache: after the first run's `rmtree`, the second `Chroma(...)` on the same path reused the cached client whose sqlite handle pointed at the deleted file. The fix was a `SharedSystemClient.clear_system_cache()` immediately after the wipe. Embeddings are dependency-injected precisely so this and the loader could be exercised with `DeterministicFakeEmbedding` on a GPU-less, `data/`-less checkout.

Outcome: `load_documents` + `ingest_collection` + `build_vector` produce two persisted Chroma indexes (`data/index/icd_db`, `data/index/rxnorm_db`) with cosine space and `doc_id` ids. All 5 new smoke tests pass, and the full suite (56 tests) is green with no regression to the ICD parser. The real embed runs on the user's 3060; on this container it is verified with fixtures + fake embeddings only. Definition-of-done for load + ingest is met; retrieval, BM25, and reranking are explicitly out of scope for this session.
